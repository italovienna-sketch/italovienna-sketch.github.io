Como eu blindei este site

Fiz uma auditoria de privacidade e segurança no meu próprio portfólio, com ajuda de IA. Cada linha abaixo foi feita e conferida neste site, em novembro de 2026.

  1. Problema

    Nome completo aparecia no site, no Google e nos PDFs do currículo.

    Decisão

    Assinar só como Italo V em tudo: páginas, metadados, dados estruturados e nome dos arquivos.

    Resultado

    Varredura do build final: zero ocorrências do sobrenome no HTML, nos scripts e nos PDFs.

  2. Problema

    Telefone e e-mail ficavam em texto puro no HTML, prato cheio para robôs de spam.

    Decisão

    Guardar os dois invertidos e em pedaços; o link real só é montado no navegador de quem visita.

    Resultado

    O HTML exportado não contém o número nem o e-mail. O botão do WhatsApp continua funcionando.

  3. Problema

    npm audit apontava 2 falhas (1 alta no PostCSS, 1 moderada no Next.js).

    Decisão

    Atualizar o Next.js dentro da versão 15 e forçar o PostCSS corrigido com override, sem pular para uma versão major.

    Resultado

    npm audit: 0 vulnerabilidades.

  4. Problema

    Sem política de conteúdo: um script injetado poderia rodar e chamar qualquer servidor.

    Decisão

    Content Security Policy que só aceita código, fontes, imagens e vídeos do próprio domínio, sem plugins e sem formulários externos.

    Resultado

    O site não faz nenhum pedido a servidores de terceiros, então o IP de quem visita não é entregue a ninguém.

  5. Problema

    Outro site podia carregar este dentro de um iframe invisível (clickjacking).

    Decisão

    Proteção no código, porque o GitHub Pages não deixa configurar cabeçalhos; e cabeçalhos completos prontos para hospedagens que deixam.

    Resultado

    Embutido em outro site, a página se esconde e tenta abrir na própria aba.

  6. Problema

    O servidor de desenvolvimento ficava visível para qualquer aparelho no mesmo Wi-Fi.

    Decisão

    Prender o servidor local em 127.0.0.1 e bloquear arquivos de senha e chave no .gitignore.

    Resultado

    Só o próprio computador abre o site em desenvolvimento.

Regra que eu sigo: só testo o que é meu ou o que tenho autorização para testar.
